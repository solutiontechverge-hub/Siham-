# Backend

## Setup
1. Copy `.env.example` to `.env`
2. Set `DATABASE_URL` (or `DB_URL`) to your PostgreSQL connection string
3. Install dependencies: `npm install`
4. Apply migrations (schema + dev seeds): `npm run migrate`
5. Run dev server: `npm run dev`

API health endpoint: `GET http://localhost:5000/api/health`

## Database IDs (UUID)

All application primary keys and foreign keys use **UUID** (`UUID PRIMARY KEY DEFAULT gen_random_uuid()`). New rows get ids from the database default unless you pass an explicit id. JSONB fields such as `service_categories` store `category_id` and `service_id` as UUID strings.

Key migration files:
- `sql/2026-05-21_migrate_to_uuid_schema.sql` — drops and recreates app tables with UUID types
- `sql/2026-05-21_seed_users_and_catalog.sql` — dev users, taxonomy, Ryan Harris Salon sample (autogenerated ids)

```bash
npm run migrate
```

The UUID schema migration **removes existing rows** in app tables. Use only when resetting dev data or after a planned production migration.

## Scripts

| Command | Description |
|---------|-------------|
| `npm run dev` | Start API with watch mode |
| `npm run start` | Start API (production) |
| `npm run migrate` | Run pending SQL migrations once |
| `npm run seed:reset` | Delete dev seed users and re-run seed (new random UUIDs) |

## API notes

- JWT payload `id` is the user UUID string.
- Route params such as calendar entry and booking ids expect valid UUIDs.
- Use `src/utils/uuid.js` helpers for parsing and validation in controllers.
